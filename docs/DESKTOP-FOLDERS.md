# 真实文件夹与玻璃档案交互

2026-09-10 用户提出：将当前阵列交互迁移到桌面真实文件夹。当前阶段为可行性评估，没有安装额外服务或读取用户目录。

## 结论

现有 Three.js 模型与拖动、波浪、抽取交互可以复用。若需要展示普通文件夹的内容，并由系统默认程序打开文件，建议网页壁纸配合一个本地程序；或将前端装入桌面应用容器。当前网页壁纸公开接口不足以单独承诺完整功能。

Wallpaper Engine 的网页 directory 属性支持图片、视频目录，不等于通用文件系统浏览。官方 openUserShortcut 文档属于 SceneScript，文档明确只允许在鼠标事件中调用，不能直接当成网页 JavaScript 接口使用。

## 推荐的后续小范围试验

由用户选择一个根目录；每列代表子文件夹、每张玻璃档案代表文件。选中显示名称、类型、大小和修改日期，点击“打开”调用系统默认程序，另提供“在资源管理器中显示”。缺失文件有明确提示，目录改动后刷新。初版不包含删除、移动、重命名，也不要求接管系统桌面图标。

本地程序只监听回环地址，用每次启动的访问凭据限制网页访问；只允许用户选定根目录下的文件，校验解析后的路径及链接目标，不接受任意命令行。网页发送文件标识，由本地程序解析已登记路径后打开。配套程序需要安装/启动/退出入口；发布时必须明确它是额外组件。

独立桌面应用能更完整地支持键盘、文件拖放和系统对话框，但嵌入桌面背景、多显示器与桌面图标的关系需要单独实机验证。不能把普通透明窗口称作已完成桌面集成。
