# 自适应阵列覆盖验证 · 2026-09-10

## 实现

旧交互窗口固定 288 个实例，关闭整组视锥裁剪。新实现使用相机视锥和阵列高度区间计算候选，再按完整卡片包围盒筛选，紧凑写入 InstancedMesh 并设置实际 count；没有通过缩放为零来保留屏幕外的绘制实例。保留屏幕边缘和附近阴影余量，标准／额外两档分别放大视锥横纵范围至 1.18／1.5。

实例缓冲容量按需增长并复用，不等于实际绘制数量；几何继续共享。射线点击使用紧凑排列后的物理单元映射。显式原片时间轴保留 159 个背景档案与一个选中模型。

暗色增加灰雾，缩短预览的雾化距离，并增强边缘淡出。亮色参数保持基线。

## 验证结果

- `check-archive-visibility.mjs`：16:9、21:9、32:9、4:3、竖屏，预览／详情镜头；独立大范围采样检查实际可见卡片不会落出候选范围，包括最高／最低位置、轨道平移与额外余量；通过。
- `reference/coverage-review.html`：Edge 实际预览检查 16:9、32:9、竖屏与竖屏详情。边角有档案连续覆盖；余量选项生效，详情内部结构与正文正常。
- 实际采样：1920×1080 暗色标准余量绘制约 277 份（候选约 399）；3840×1080 绘制约 492 份（候选约 699）；1080×1920 预览约 272 份，竖屏详情额外余量约 213 份。数量随镜头状态变化。这些不是对旧版的帧率提升百分比。
- `reference/loop-review.html`：61 次连续循环切换、9 个实际射线点击、数千行列坐标重置、详情净空、先转正后归位与快速重新选中均通过。原片四个时间点保持 159 个背景位置，最大位置误差 5.48e-7。
- 原有循环、运动、档案、自由拖动与惯性、主题、律动、视口检查通过。
- `check-array-input.mjs` 依赖当前未安装的 Playwright，未执行浏览器步骤；使用上面的实际场景射线验证与纯拖动／惯性检查补充覆盖。

## 性能边界

裁剪降低同等覆盖范围内无须提交的实例数，但超宽屏补齐缺失部分可能比旧版 288 份更多。全屏后期处理成本和卡片互相遮挡的片元成本仍存在。浏览器受后台节流与宿主模拟帧率限制，不能把这些检查作为真实 WE 帧率基准；本机壁纸更新后由宿主试用确认实际表现。

普通构建与 Wallpaper Engine 构建均通过，沿用既有单包体积提示。
