# 模型精度三档对照

2026-09-12。基于 `codex/visual-preserving-performance`，高档是已经完成上一轮无损渲染优化的版本，不是优化之前的版本。本轮评估“只改变模型几何精度”的额外收益。

## 档位

| 模型精度 | 每张背景卡片三角形 | 当前选中／详情模型三角形 | 处理方式 |
| --- | ---: | ---: | --- |
| 高 | 4,200 | 82,348 | 原始生产模型 |
| 中 | 2,072（减少 50.7%） | 82,348 | 仅背景螺丝、边框减面 |
| 低 | 1,554（减少 63.0%） | 21,869（减少 73.4%） | 背景进一步减面，近景内环、内构曲面、刻线和螺丝等减面 |

数字来自实际加载到 Three.js 的几何，包含近景动态标签平面，不将原资源中生产渲染已排除的 Carbon_Ink 算入。两个螺丝所属表面原有 2,136 面，中档为 384 面，低档为 148 面。

所有档位沿用相同分辨率、灯光、材质、玻璃折射、AO、景深、阴影、相机和动作。没有隐藏螺丝或减少阵列覆盖，也没有更换为超级性能模式。盖板等未简化表面直接复用原始几何，不经过 Blender 再导出替换，避免无关的精度变化。

## 实现与复现

- `art/model_precision.py` 通过 Blender MCP 执行，来源为 `public/assets/archive-cassette.glb`；源 SHA256 记录在 `reference/model-precision/{medium,low}.json`。
- 脚本按自身位置确定仓库根目录，支持独立壁纸仓库。Blender MCP 中使用 `import runpy; runpy.run_path('实际仓库路径/art/model_precision.py', run_name='__main__')`，不将资产写入另一仓库。
- `art/model-precision.blend` 保留两个实验场景。先合并 glTF 法线／UV 接缝上的重合顶点，再 Decimate，最后从原始模型传递法线。首版未合并顶点的低档产生较明显分面，已修正；早期 smoke 样本不作为最终结果。
- `reference/model-precision.ts` 只在对照页替换指定表面的几何，保留生产场景的材质对象；中档近景完全使用原模型。位置包围盒的偏差过大会直接报错。
- 对照入口 `reference/model-precision.html` 提供高／中／低、六种场景、亮暗色与暂停，可用 `npm run dev` 在 `/reference/model-precision.html` 打开。
- `node scripts/build-model-precision.mjs` 构建独立试验包至 `release/model-precision`。本轮没有将实验资产接入正式画质设置、PWA 资源或创意工坊。

```powershell
$env:PLAYWRIGHT_MODULE='C:/Users/LBLC/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright'
node scripts/build-model-precision.mjs
node scripts/check-model-precision.mjs
node scripts/check-model-precision.mjs --host
$env:PNGJS_MODULE='C:/Users/LBLC/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pngjs'
node scripts/summarize-model-precision.mjs
```

宿主测试使用 Wallpaper Engine 的独立隐藏测试窗口，名称为 `Rhine model precision diagnostic`，测试后自动关闭。不会替换正在使用的壁纸。`WALLPAPER_EXE` 可覆盖可执行文件路径。浏览器与宿主测试顺序运行，避免相互占用 GPU。

## 测量方法

本机 RTX 5070 Ti Laptop GPU，ANGLE / D3D11，1920×1080、DPR 1、原始画质（32 采样 AO、全分辨率 AO／折射、2048 阴影、景深开启、SMAA 关闭）。每档六场景：静止归齐、呼吸、连续选档、稳定详情、近景旋转、音乐律动。

三轮顺序为高→中→低、低→高→中、中→低→高。每场景先运行相同的 60 帧输入预热，再重新稳定并绘制 60 帧，最后记录 96 帧。汇总使用“每轮中位数的中位数”，同时保留三轮范围。GPU 时间来自 `EXT_disjoint_timer_query_webgl2`，无效查询为 null；CPU 时间为 `scene.update()` 同步耗时，不与 GPU 时间相加解释成端到端帧时间。

固定动画时间步、随机核与输入。自动校验每档的相机、选档、阵列数量、旋转角度、画质配置和实例上传字节一致。逐帧 draw calls 也进行比较：低档连续选档在第 76 帧多出 3 次绘制（358→361），两端三轮均重复出现；这与几何简化改变局部包围球后的边缘裁剪变化一致，其余帧一致。该例外保存在汇总里，低档并未靠减少 draw calls 获得收益。原始采样和截图统计见 `model-precision/browser/` 与 `model-precision/host/`。

扩展 TypeScript 检查（包含三个 reference 脚本）、独立对照包构建、两端合计 108 组场景采样及不变量校验通过。对照页的高／中／低切换、详情旋转状态、暗色、暂停和恢复通过实际 Edge 页面检查，记录在 `model-precision/review-check.json`。性能测试结束后才执行对照页交互检查，避免额外页面同时渲染影响采样。

## 实测结果

GPU 时间单位为 ms，越低越好；括号为相对高档的下降幅度。

### Edge 网页版（152）

| 场景 | 高 | 中 | 低 |
| --- | ---: | ---: | ---: |
| 阵列呼吸 | 4.682 | 4.279（8.6%） | 4.205（10.2%） |
| 连续选档 | 5.391 | 5.008（7.1%） | 4.736（12.1%） |
| 近景旋转 | 5.468 | 4.982（8.9%） | 5.009（8.4%） |
| 音乐律动 | 4.989 | 4.270（14.4%） | 4.124（17.3%） |
| 静止归齐／稳定详情 | 0 | 0 | 0 |

### Wallpaper Engine 原生 CEF（Chrome 146）

| 场景 | 高 | 中 | 低 |
| --- | ---: | ---: | ---: |
| 阵列呼吸 | 4.721 | 4.316（8.6%） | 4.214（10.7%） |
| 连续选档 | 5.812 | 5.438（6.4%） | 5.308（8.7%） |
| 近景旋转 | 5.253 | 4.803（8.6%） | 4.650（11.5%） |
| 音乐律动 | 4.686 | 4.254（9.2%） | 4.156（11.3%） |
| 静止归齐／稳定详情 | 0 | 0 | 0 |

本次数据支持模型精度作为额外性能选项，但不支持“面数减少一半就能大幅提高帧率”。中档在网页动态场景降低 GPU 耗时约 7%–14%，宿主约 6%–9%；低档分别约 8%–17% 和 9%–12%。从中档进一步降到低档，宿主动态场景仅再降低约 2%–3% 的 GPU 耗时；网页近景旋转低档甚至比中档稍慢约 0.5%，落在本机采样波动范围内。

CPU 没有一致、明显的下降。例如宿主阵列呼吸三档 CPU 中位数都是 2.50ms，连续选档为 4.20／4.10／3.90ms，音乐为 2.40／2.30／2.50ms。正常动态帧 draw calls 仍为 75，连续选档中位数仍为 273。模型面数下降不改变像素覆盖范围、玻璃折射或后处理次数，这与观测到的有限收益相符；本轮没有单独计时各 Shader 阶段，不能据此给它们分配精确成本比例。

几何的确减少：呼吸场景各渲染通道累计三角形中位数为 4,313,825／2,283,713／1,608,104。该数值包含重复通道绘制，不是场景中唯一三角形数。三档动画上传量相同（呼吸为 20,320 字节／帧）。

推荐先保留高档作为原画基准，中档作为较保守的节能选择，低档作为允许细节变化的可选项。低档的额外视觉代价是否值得，需要用户在自己的设备上比较；这些测试不代替用户的视觉确认。

## 视觉与适用范围

中档保留完整近景，但背景螺丝和边框的轮廓／高光有变化。低档近景的螺丝、刻字、圆环细微边缘及高光有可见差别；不能称为逐像素无损。正常尺度与近景旋转需结合对照页自行判断是否接受。首轮阵列呼吸与近景旋转的高、中、低截图随报告保留，其余截图可由脚本复现。

静止场景在上一轮优化后已经复用画面，三档均无需重复 GPU 绘制，所以降低模型精度不会进一步改善其稳定后的三维绘制成本。仍存在界面、模拟、系统桌面合成等开销，不能将三维零绘制解释成壁纸整体零资源占用。

这些是本机数据，不是低配电脑、核显或真实 iPhone 的结果。显卡频率没有锁定，测试顺序交错只能减轻温度、频率和后台活动的影响。此次测的是加载完成后的持续渲染，不评价下载时间或峰值内存；实验页先加载原模型再替换几何，不适合作为正式资源加载方案的体积基准。
